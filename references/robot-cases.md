# URDF static analysis contract

Use `schema_version: "robot-1.0"` with `analyze case.robot.json --out fresh-directory`. Runnable examples are in `examples/robots`: a fixed-base arm over three poses, a declared-ground-contact case and a tipping overload. All numerical reference masses, actuator limits and material parameters are prescribed assumptions, not certified components.

The case specifies `model.path` to expanded URDF, optional explicit `package_roots`, nonempty `poses` with named `joints`, `gravity_m_s2`, payload point masses, external force/couple loads, fixed or contact base, effort safety factor, physical verification conditions, optional component FEM templates, required component links and generation provenance. Unknown keys are rejected. Relative paths resolve against the case/URDF file as appropriate. An unresolved xacro, missing asset, disconnected/cyclic tree, invalid inertia, missing pose coordinate or out-of-limit pose is an invalid analysis.

URDF geometry/inertials use metres, radians, kilograms and kg m². Mesh `scale` is retained in provenance; meshes must resolve through a local path or explicitly mapped package root. Missing inertials are not silently treated as zero mass: use `massless_links` for declared coordinate-only links. Revolute, continuous, prismatic and fixed joints are supported. Floating/planar joints need a different posed-root/dynamic model. Axis is in the joint frame; RPY is `Rz(yaw) Ry(pitch) Rx(roll)`, and origin precedes joint motion. Independent moving coordinates must all be supplied. Mimic positions are derived and cycle checked; independent actuator effort includes multiplier-weighted joint efforts by virtual work. Gear efficiency, linkage strength and transmission compliance are not inferred from a mimic tag.

Payloads: `{name, link, mass_kg, center_m, scalable?}`. Loads: `{name, link, force_n, moment_n_m?, position_m, frame: "link" | "world", scalable?}`. Payload centers are link-local; explicit loads use their stated frame. Robot-link weight and `scalable:false` loads remain fixed while payload patterns scale. Static Newton–Euler propagation returns subtree force/couple, local holding efforts, independent actuator efforts, world frames, total mass/COM and foundation wrench. URDF `effort` limits or explicit independent `effort_limits` are declared model limits; `actuator_ratings_verified` must reflect actual service/continuous capability for a prediction.

`base: {type:"contacts", points_world_m:[[...]], friction_coefficient:...}` requests static support equilibrium on one horizontal plane. Contact normal forces are nonnegative; a conservative friction diamond enforces `|fx|+|fy| <= mu*fz`. The linear program checks all six force/moment equations and can bound a scalable payload. Numerical solver failures invalidate the analysis. Infeasible equilibrium signals possible tipping/slip under those assumptions. This does not assess dynamic balance, foot/ground strength or actual friction calibration.

## Component finite elements

Rigid statics alone cannot establish link strength. Each `components` item names a `link`, a solid `case_path`, explicit load `ports` mapping child joint/load/payload names to surface selectors, and optional `link_from_component: {xyz_m,rpy_rad}`. The template supplies actual material/failure/fixture data, mesh sizes and criteria; its upstream support is an ideal fixed interface. Source density-volume mass and transformed geometry COM must match the URDF link within declared tolerances. No collision/visual mesh is substituted silently.

Downstream subtree wrenches are transferred to their ports, rotated into the component frame, applied at their actual joint/link locations, and split into fixed/scalable parts. N m becomes N mm for the FEM backend. The component's own gravity is applied volumetrically. Both reference and fixed-load subcases undergo equilibrium checks; three meshes and conditional-limit guards remain mandatory. Required component FEM must be present. Reports list links without FEM and preserve each analyzed component's omitted mechanisms, including buckling unless explicitly requested.

The robot-level payload multiplier is the common lower bound across supplied poses, known actuator limits, requested contacts and analyzed components when all stated conditions and component limits are available. It covers exactly this declared model and coverage; it is not an overall robot rating. Unassessed links, mounts, transmission, contacts, dynamics and manufacturing remain explicit. Robot result/signal contracts are `robot-result-1.0` and `simplecae-signal-1.0`.

Optional `elastic_transfer` evaluates first-order parent-section translation and rotation through a fixed-base tree at the requested loads. Read [requirements and limitations](contact-and-transfer.md) before enabling it. It requires explicit FEM/rigid coverage and locked-joint assumptions and withholds the robot payload multiplier; the default independent-component behavior is unchanged.

Explicit independent scalar joint springs can be used alongside link FEM. Read [joint compliance](joint-compliance.md) for complete joint coverage, output-side stiffness units, operating-state sources, vector contributions and first-order boundaries. Default locked-joint behavior is unchanged; this is not a coupled continuum/control model.
